## <a id="-overview"></a>🔭 Overview

**Visual Graph Programming (VGP)** is a multi-platform codebase visualization and automation tool. It parses source code with **Tree-sitter** into a queryable **code property graph** stored in an embedded graph + vector database (**GrafeoDB**), and renders it as an interactive, mathematically-optimized node graph that stays **bidirectionally synchronized** with the underlying text — click a node to jump to the line of code, edit the code and watch the graph rewire.

The project targets three deployment surfaces, built on one shared core:

1. **IDE Extension (VS Code)** — visualize dependency/call graphs inside the editor, with LSP-backed semantic navigation.
2. **Game Engine Plugin (Unreal Engine)** — a bidirectional, node-based visual scripting interface over native C++ (and eventually Verse), replacing binary Blueprints with text-as-source-of-truth graphs.
3. **Standalone App (Tauri)** — a fully isolated desktop application for enterprise-scale codebases, with a Python ML sidecar for Graph-RAG and LLM-assisted structural reasoning.

The design and rationale behind every architectural choice are documented in the research reports under [`prisma/`](prisma/).

### Why VGP?

| Problem | VGP's Answer |
| --- | --- |
| Text search (grep/regex) drowns in noise on large C++/Python/Go codebases | AST → knowledge-graph extraction enables deterministic, multi-hop structural queries |
| Force-directed graph layouts collapse into unreadable "hairballs" | Operations Research layout engine (stress majorization / MIP) with guaranteed readability |
| Standard RAG hallucinates on multi-hop code questions | Graph-RAG over the code property graph, with hybrid graph + vector retrieval in one database |
| Binary visual scripts (Blueprints) can't be diffed or merged | Text remains the single source of truth; the graph is a synchronized projection of it |

## <a id="-features"></a>✨ Features

### Core Capabilities

- 🌳 **Incremental parsing** — Tree-sitter based pipeline that updates only affected subtrees in under a millisecond, error-tolerant during live editing
- 🕸️ **Code Property Graph** — unified AST + control-flow + data-flow multigraph, ingested into embedded GrafeoDB with Cypher/GQL querying
- 🔍 **Hybrid graph + vector search** — code embeddings stored alongside graph nodes; multi-hop traversals fused with semantic similarity (RRF)
- 🧮 **OR-optimized layouts** — deterministic hierarchical layouts via stress majorization and mixed-integer programming instead of force-directed chaos
- ↔️ **Bidirectional navigation** — click a node to jump to the exact source line; select code to highlight its node; round-trip graph ⇄ text editing
- 🧠 **Graph-RAG / MCP integration** — Python sidecar exposes the graph to LLM agents via the Model Context Protocol for structurally-grounded reasoning
- 🧩 **VS Code webview visualization** — React Flow graph rendering with LSP call-hierarchy extraction, semantic filtering, and PlantUML/Mermaid export
- 🎮 **Unreal Engine graph editor** — UEdGraph/Slate node interface over native C++ with lossless (comment/whitespace-preserving) AST splicing and Live Coding integration
- 🖥️ **Standalone Tauri app** — native-webview desktop application with Rust core, C++ parsing engine, and Python ML sidecar processes
- 📊 **Semantic visual diffing** — graph-level highlighting of added/removed/changed nodes between commits, plus execution-flow vs data-dependency view modes

### Tech Stack

| Layer | Technology | Role |
| --- | --- | --- |
| **Core / Parsing** | C++20, [Tree-sitter](https://tree-sitter.github.io/), [GrafeoDB](https://github.com/GrafeoDB/grafeo), CMake, [pixi](https://pixi.sh/) | Incremental parsing, graph construction, embedded graph + vector storage |
| **Backend / ML** | Python 3.12+, PyTorch, NetworkX, OR-Tools, [uv](https://github.com/astral-sh/uv) | Graph-RAG, embeddings, layout optimization, MCP server, sidecar orchestration |
| **IDE Extension** | TypeScript, VS Code Extension API, React Flow, Tree-sitter WASM | In-editor graph visualization and navigation |
| **Standalone App** | [Tauri 2](https://tauri.app/) (Rust), React 19, TypeScript, Vite | Cross-platform desktop UI with sidecar process management |
| **Engine Plugin** | Unreal Engine 5+ C++, Slate/UEdGraph, WebSockets | Bidirectional C++ visual scripting inside the Unreal Editor |
| **Tooling** | npm workspaces, Cargo workspace, GitHub Actions, Codecov, Dependabot | Monorepo orchestration, CI/CD, coverage, automation |

## <a id="-architecture"></a>🏗️ Architecture

```
 ┌────────────────────────────┐   ┌──────────────────────────────┐
 │  VS Code Extension (TS)    │   │  Unreal Engine Plugin (C++)  │
 │  webview + React Flow      │   │  Slate / UEdGraph editor     │
 └─────────────┬──────────────┘   └──────────────┬───────────────┘
               │  IPC / WebSockets               │
 ┌─────────────▼─────────────────────────────────▼───────────────┐
 │                    C++ Base Module (base/)                    │
 │   Tree-sitter parsing  →  graph schema  →  GrafeoDB ingest    │
 └─────────────┬─────────────────────────────────┬───────────────┘
               │ bindings / stdio                │
 ┌─────────────▼──────────────┐   ┌──────────────▼───────────────┐
 │  Python Backend (backend/) │   │  Tauri App (app/)            │
 │  Graph-RAG · MCP · layouts │   │  Rust core + React 19 UI     │
 └────────────────────────────┘   └──────────────────────────────┘
```

### Repository Layout

```
Visual-Graph-Programming/
├── base/               # C++ core: parsing pipeline, graph engine (pixi.toml, CMakeLists.txt)
├── backend/            # Python ML/Graph-RAG sidecar (deps in root pyproject.toml)
├── extension/          # VS Code extension (TypeScript, package.json)
├── app/                # Tauri + TypeScript standalone app
│   └── src-tauri/      # Rust core of the Tauri app (Cargo.toml, member of root workspace)
├── plugin/             # Unreal Engine plugin (created in the engine-plugin phase)
├── prisma/             # Research reports driving the architecture
├── moon/               # ROADMAP.md and CHANGELOG.md
├── git/                # codecov.yaml, CONTRIBUTING.md
├── github/             # Project-board automation suite (scripts, hooks, config)
├── .github/            # Workflows, issue/PR templates, Dependabot
├── package.json        # npm workspaces root (extension + app)
├── Cargo.toml          # Cargo workspace root (app/src-tauri + future Rust modules)
├── pyproject.toml      # Python project (backend + CI tooling deps)
└── pixi.toml           # C++ toolchain & native dependency environment
```

## <a id="-installation--setup"></a>📦 Installation & Setup

### Prerequisites

```bash
# Check required tools
cmake --version    # 3.24+
python3 --version  # 3.12+
node --version     # 20+
rustc --version    # 1.80+
```

**Linux system packages (Tauri + webview):**

```bash
sudo apt update
sudo apt install -y build-essential curl wget file libssl-dev \
  libgtk-3-dev libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev
```

**macOS:** `xcode-select --install` &nbsp;|&nbsp; **Windows:** [VS C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) + [WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)

### C++ Base Module (pixi + CMake)

The C++ environment (compilers, CMake, Ninja, Tree-sitter, test frameworks) is managed by [pixi](https://pixi.sh/):

```bash
# Install pixi (once)
curl -fsSL https://pixi.sh/install.sh | bash

# From the repo root: install the C++ toolchain environment
pixi install

# Configure and build the base module
pixi run configure     # cmake -S base -B base/build ...
pixi run build         # cmake --build base/build

# Or manually
cmake -S base -B base/build -DCMAKE_BUILD_TYPE=Release
cmake --build base/build --parallel
```

### Python Backend Module (uv)

```bash
# Install uv (once)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create the venv and install all backend + dev dependencies
uv sync --all-extras

# Activate
source .venv/bin/activate   # Linux/macOS
.venv\Scripts\activate.ps1  # Windows PowerShell
```

Alternatively with pip: `pip install -e ".[backend,dev]"`.

### TypeScript Modules (npm workspaces)

The root `package.json` declares npm workspaces for `extension/` (VS Code extension) and `app/` (Tauri UI). One install covers both:

```bash
# From the repo root — installs extension/ and app/ dependencies
npm install

# Or per-workspace
npm install --workspace=extension
npm install --workspace=app
```

### Rust / Tauri (Cargo workspace)

The root `Cargo.toml` defines a workspace containing `app/src-tauri` (and any future Rust modules):

```bash
# Fetch and build all Rust workspace members
cargo build

# Tauri CLI (installed as a dev dependency of app/, no global install needed)
npm run tauri --workspace=app -- --help
```

## <a id="-running"></a>🛠️ Running

### Standalone Tauri App

```bash
# From the repo root (delegates to the app workspace)
npm run dev:app

# Or directly
cd app && npm run tauri dev
```

First run compiles the Rust backend — expect several minutes on a cold cache.

**Production build:**

```bash
npm run build:app
# Bundles to: app/src-tauri/target/release/bundle/
```

### VS Code Extension

```bash
# Compile the extension
npm run build:extension

# Launch an Extension Development Host
cd extension && code .
# Press F5 (Run > Start Debugging) in VS Code
```

Package a `.vsix` with `npm run package --workspace=extension`.

### Python Backend / MCP Sidecar

```bash
source .venv/bin/activate

# Run the backend module (Graph-RAG / layout / MCP server entry points land here)
python -m backend
```

### Unreal Engine Plugin

The plugin phase begins after the core library is stabilized (see [Roadmap](#-roadmap)). Once available: copy/symlink `plugin/` into your project's `Plugins/` folder, regenerate project files, and enable *Visual Graph Programming* in the Plugins browser.

## <a id="-testing"></a>🧪 Testing

```bash
# All TypeScript tests (extension + app), from the repo root
npm test

# Per workspace
npm run test --workspace=extension
npm run test --workspace=app

# Python tests
uv run pytest

# C++ tests (GoogleTest via CTest)
pixi run test
# or: ctest --test-dir base/build --output-on-failure

# Rust tests
cargo test
```

**Linting & formatting:**

```bash
uv run ruff check .          # Python lint
uv run mypy backend          # Python types
npm run lint                 # TS/JS lint (all workspaces)
cargo fmt --check && cargo clippy   # Rust
```

Coverage is aggregated per-module and reported to Codecov — see [`git/codecov.yaml`](git/codecov.yaml) for flags and targets.

## <a id="-project-automation"></a>🤖 Project Automation

This repo ships an LLM-assisted project-board automation suite under [`github/`](github/README.md):

## <a id="-roadmap"></a>🗺️ Roadmap

Development proceeds in phases — core-first, then thin host wrappers:

1. **Phase 0–1: Core + Backend** — C++ parsing/graph engine, GrafeoDB ingestion, Python Graph-RAG & layout services
2. **Phase 2: IDE Extension** — VS Code webview visualization over the shared core
3. **Phase 3: Unreal Engine Plugin** — asset-registry ingestion, C++ visual scripting, WebSocket bridge
4. **Phase 4: Standalone Tauri App** — full isolation, sidecar orchestration, enterprise-scale graphs

See [`moon/ROADMAP.md`](moon/ROADMAP.md) for the detailed per-milestone implementation steps, and [`moon/CHANGELOG.md`](moon/CHANGELOG.md) for release history.
